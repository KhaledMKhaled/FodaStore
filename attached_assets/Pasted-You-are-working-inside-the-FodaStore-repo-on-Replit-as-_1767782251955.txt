3) IMPLEMENTATION DETAILS (MANDATORY)
============================================================

3.1 Backup Flow
When admin clicks “إنشاء نسخة احتياطية”:
A) DB Backup
- Run: pg_dump (schema + data) into db.dump (custom format preferred)
- Ensure consistent snapshot:
  - If possible, use one transaction/snapshot options appropriate for Postgres
- Record db.dump size

B) Media Backup (Object Storage)
- Determine the media scope:
  - Prefer backing up ONLY objects referenced by DB (shipment item image keys/urls) to keep it tight
  - OR if bucket is small, allow backing up a specific prefix used by this app (e.g., uploads/items)
- Produce a list of object keys to fetch
- Download objects and write to local temp dir preserving key paths under media/
- For each file, compute SHA256
- Write checksums.txt

C) manifest.json
Include:
- createdAt
- app version/commit if available
- db dump format and size
- list of tables counts (at least: shipments, shipment_items, payments, inventory_movements, suppliers, exchange_rates, audit_logs)
- media objects count + total size
- storage prefix/key strategy description

D) ZIP everything into one file
- foda-backup-....zip

E) Mark job completed and provide download endpoint

3.2 Restore Flow
When admin uploads ZIP and confirms:
A) Enter maintenance mode
- Block writes (shipments/payments/suppliers/exchange rates/inventory updates)
- Only allow admin to see restore progress

B) Validate ZIP structure
- Must contain db.dump, manifest.json, checksums.txt, media/
- Validate checksums for all files present

C) Restore DB
- Use pg_restore to restore FULL DB
- If in-place restore is used:
  - Ensure you safely drop/recreate schema
  - Ensure extensions required (e.g., pgcrypto) exist
- Prefer safer approach if possible:
  - Restore into a new schema then swap
  - Or transactional pattern where feasible

D) Restore media
- Upload each media file to object storage with the SAME key paths as in media/<key>
- After upload, verify by a HEAD/GET call or SDK metadata call
- Ensure permissions/public access align with how the app serves images today

E) Exit maintenance mode
Only after both DB and media restore succeed.

3.3 Error handling
- No generic “حدث خطأ”
- Show clear Arabic messages for admins
- Log full details server-side
- Ensure partial failures are detectable and reported
