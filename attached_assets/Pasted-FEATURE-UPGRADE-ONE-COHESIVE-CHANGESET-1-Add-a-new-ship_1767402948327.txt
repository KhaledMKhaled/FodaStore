PHASE A — "النواقص" STEP (MISSING PIECES) + COSTING + INVENTORY
============================================================

Business Problem:
When a shipment is received, some pieces may be missing (lost during shipping/customs/etc).
Those missing pieces must:
- Reduce shipment final total cost (they should not be counted in landed totals).
- Reduce inventory quantities to match actual received pieces.
- Be visible and auditable.

------------------------------------------------------------
A1) Wizard Step Placement
------------------------------------------------------------
Add a new wizard step label (Arabic RTL): "النواقص"
Step order becomes:
- Import
- Shipping Details
- Customs & Takhreeg
- النواقص (NEW)
- Summary / Inventory / Final

This step must only be accessible after Customs & Takhreeg has been completed (shipment effectively received).

------------------------------------------------------------
A2) UI Requirements (Arabic RTL)
------------------------------------------------------------
In "النواقص" step, show a table of shipment items with:
- item image thumbnail (if exists)
- item name
- CTN (cartons)
- total pieces (original, before missing)
- missing pieces input (عدد النواقص)
- actual pieces (final received = original - missing)
- unit landed cost display (broken down by components if available)
- missing cost subtotal display

Live totals at bottom:
- إجمالي القطع الناقصة
- إجمالي تكلفة النواقص (جنيه) [and RMB if your system tracks RMB totals]
- صافي إجمالي تكلفة الشحنة بعد خصم النواقص (جنيه)

Validation:
- missingPieces integer >= 0
- missingPieces <= originalPieces
- show clear Arabic inline errors

------------------------------------------------------------
A3) Data Model (Required)
------------------------------------------------------------
Persist missing pieces per shipment item.

Either:
- Add shipment_items.missing_pieces INT DEFAULT 0
OR
- Create a dedicated table (shipment_item_missing)

Source of truth must be item-level.

Add audit logging for missing updates:
- entity_type: shipment / shipment_item
- action_type: missing_pieces_updated
- include full details (old/new missing, user, timestamp)

------------------------------------------------------------
A4) Calculation Rules (Must Match Existing Allocation Logic)
------------------------------------------------------------
Missing cost must be based on FULL LANDED UNIT COST (same basis used for inventory posting):
For each item:
missingCostItem = missingPieces * unitLandedCost(item)

unitLandedCost must include the item’s allocated shares of:
- purchase cost (RMB -> EGP if needed)
- commission share
- shipping share
- customs share
- takhreeg share

Then:
shipment.final_total_cost_egp must decrease by totalMissingCostEGP.

If your system tracks RMB totals separately, apply consistent logic but do NOT mix currencies.

------------------------------------------------------------
A5) Inventory Impact (Mandatory)
------------------------------------------------------------
Inventory must reflect actual received pieces after missing.

Preferred auditable approach:
- Keep original inventory stock-in movement as-is OR adjust carefully based on repo conventions.
- Create an additional inventory movement of type "missing_adjustment" (or similar) for each affected item:
  - pieces_out = missingPiecesDelta
  - cost_out_egp = missingPiecesDelta * unitLandedCost
This preserves auditability and avoids rewriting history.

Idempotency and updates:
- If user edits missingPieces later, apply deltaMissing = new - old.
- If deltaMissing > 0: add more pieces_out
- If deltaMissing < 0: reverse via pieces_in adjustment movement (or repo-approved reversal pattern)
Do not duplicate movements.

Make it clear and RTL-correct.
